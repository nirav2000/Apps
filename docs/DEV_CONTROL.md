# Development Control Centre

## Purpose
One source of truth for unfinished work across all apps and shared components. GitHub stores the records; the Apps dashboard is the normal user interface.

## Status flow
Inbox -> Next -> In Progress -> Verify -> Done. Use Explore for research and Waiting for external dependencies.

## Issue fields
Every central development item should record when known: Status, App, Type, Priority, Target date, Repository, Branch/version, URL, Shared component, Context, Action, Acceptance/verification, Dependencies, and source context.

## #dev capture
When the user writes `#dev`, capture the thought with minimal effort from the user. Infer metadata from the current conversation rather than asking for a form. Resolve relative dates such as tomorrow to a concrete date. Preserve uncertainty rather than inventing details. If an existing tracker item covers the same work, update/consolidate it rather than creating a duplicate.

## Principle
The user should not need routine GitHub navigation. ChatGPT performs structured capture and maintenance; the Development Control dashboard presents the useful views.
